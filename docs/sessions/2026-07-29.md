## 1. Stabilisation before the revamp (landed on `main`)

- **Turbopack would not start.** Root cause was NOT the error message. `next`
  WAS resolvable from `app/`. Real cause: Windows path-casing split — pnpm had
  written `node_modules/.pnpm` symlink targets as `D:\projects\…` while
  `pnpm run` normalises cwd to canonical `D:\Projects\…`. Turbopack compares
  case-sensitively, decided `next` was "outside the project directory", refused
  to compile. Fix: wipe `node_modules`, reinstall from the canonically-cased
  path, plus `turbopack.root: __dirname` as belt-and-braces.
- Fixing that also killed a downstream `InvariantError: Expected
  workUnitAsyncStorage to have a store` on `/blogs/typescript` — same
  duplicate-module-identity problem.
- `eslint` key removed from `next.config.ts` (Next 16 dropped it).
- **Dead `overrides` block removed from `package.json`.** It pinned
  `@types/react` to a React 19 **RC** types package. pnpm ignores npm's
  top-level `overrides` entirely (confirmed: no `types-react` in the lockfile),
  so it did nothing for installs — but it made every `npx` call in the repo die
  with `EOVERRIDE`, which is why the **shadcn MCP was failing to connect**.
- AI SDK stack removed wholesale: `app/api/chat`, `lib/tool.ts`,
  `components/summary/*`, `components/prompt-kit/*`, `SYSTEM_PROMPT`, `DATA`,
  and 10 orphaned packages. Compile time 34s → 13s.
- `baseline-browser-mapping` warning is **unfixable from here** — Next bundles
  its own `browserslist`. Installed it, confirmed no effect, removed it again.

## 2. Palette + type system

- Monotone warm-neutral, chroma capped at `0.006`. Light = stone
  `oklch(0.968 0.004 85)`, dark = graphite `oklch(0.178 0.004 80)`.
  Muted-on-bg ≈ 4.9:1 light / 7:1 dark, both AA.
- **Bug found:** `:root` and `.dark` were each defined **twice** in
  `globals.css`, once unlayered and once inside `@layer base`. Unlayered beats
  layered, so the second block was dead. Collapsed to one.
- **Display face: Space Grotesk** (`--font-display`). Ran a 7-font bake-off
  with a temporary in-page switcher. I argued for Instrument Serif then Syne;
  the human picked Space Grotesk. **Both my picks were wrong in the same way**
  — high-contrast serifs read fashion/literary, not software. Genre was wrong
  before the individual font was.
- `.label` = the micro-label device: `font-mono text-[10px] uppercase
  tracking-[0.18em] text-muted-foreground`. **Must live in `@layer components`**
  — unlayered it beat `hover:text-*` utilities and silently killed every hover
  state using it.
- Container widened `max-w-3xl` → `max-w-5xl`.

## 3. Hero

- Structure: rail (location left / resume right) → name → bio → actions strip.
- `SOUGATA DAS` / `REACT DEVELOPER`, Scalzo alignment. **The effect is line two
  overhanging line one on the right**, which only works if the two sizes stay
  close (0.84 ratio) and line two is stepped in. An earlier 0.65 ratio was too
  small to ever reach past line one.
- `wide:min-h-[88svh]` — custom variant on `min-aspect-ratio: 1/1`. Keyed on
  **viewport shape, not width**: iPad Mini portrait is 768px (past `md`) and
  stretched just as badly as a phone. On portrait there is no min-height, so
  the paddings are deliberately larger there.
- Mask reveal needs `pb-[0.12em] -mb-[0.12em]` on the overflow wrapper or tight
  leading clips descenders.

## 4. Nav, theme, 404

- Nav is one typeface, one case, one weight, one size (`font-mono text-sm
  font-medium lowercase`, muted). Several rounds to get there: matched *numbers*
  produced mismatched *apparent* size, because `sougata` is nearly all x-height
  while `work`/`posts` carry ascenders and descenders.
- Theme: `ThemeShortcutProvider` (Ctrl/Cmd + D, `preventDefault` because that is
  bookmark, ignores typing contexts) **plus** a visible toggle. Shortcut-only was
  an accessibility regression.
- **404 escapes the chrome** by moving nav/footer out of the root layout into
  `app/(routes)/layout.tsx`. You cannot escape the *root* layout.
- `notFound()` does **not** unwind layouts — it renders the boundary component
  inside the layouts above the throwing segment. Fixed with
  `dynamicParams = false` on `blog/[slug]`, so unknown slugs are unmatched URLs
  rather than rendered-then-errored. **That flag is load-bearing for the 404
  shell**, not just leftover from static export.
- 404 SEO: my first pass emitted a **duplicate robots tag** (Next auto-injects
  `noindex` on not-found) and wrongly set `nofollow`, which would have blocked
  crawlers from the recovery links. Trimmed to Next's own tag.

## 5. Skills band

- One line, six disciplines, em dashes as **separator glyphs** (exempt from the
  no-em-dash rule in `CLAUDE.md`, noted in-file).
- Scroll-driven fill. **Colour is never animated** — text is always
  `text-foreground` and only *opacity* moves 0.18 → 1. Opacity is a compositor
  property; animating `color` (or `background-clip` gradients, or `clip-path`)
  repaints text every frame, which is the jitter. Per-word slices overlap 60%
  so the sweep reads continuous.
- **Disabled on mobile.** The hero is content-height on portrait so the band is
  already on screen at load, meaning the fill starts mid-sweep and you land on
  half-lit text. Mobile is uniformly `text-muted-foreground` at opacity 1.
- Bug: passing `style={undefined}` when disabling left Framer's last inline
  opacity on the element (stuck half-lit). Must pass `{ opacity: 1 }` explicitly.

## 6. Experience

- Three-column grid (company 5 / role 4 / date 3) spanning the full measure.
  Two columns pushed to opposite edges left ~500px of dead middle.
- `md:items-center`, not `items-baseline` — 30px name against 11px labels on a
  shared baseline left the small type sitting low.
- Mobile: `md:contents` dissolves the right-hand wrapper at `md` so its two
  children drop into the grid. Date first in source order (mobile wants it on
  top), `md:order-*` restores reading order on desktop.
- **"Personal Projects" entry deleted.** Not experience, redundant with the
  Projects section, and the three-column layout exposed `Remote` on one's own
  projects as meaningless.
- Section has **no bottom padding** — the last row's `py-7` closes it, so adding
  a company extends the list naturally instead of stacking paddings.

## 7. Projects — the long dance (four full pivots)

Chronological, because the reasoning matters more than the endpoint:

1. **Paper Shaders `MeshGradient`, monotone.** I argued for shaders over images
   on theme reactivity + zero asset weight. Built per-project ramps, `speed={0}`
   with `frame` as seed.
2. **Human: "all metallic and similar."** Correct — with chroma near zero the
   only remaining variable is lightness, so everything converges. I had
   over-applied the monotone rule; the Scalzo reference is monochrome *chrome*
   with **colour in the work**. Added desaturated hues.
3. **AI images** (clouds / misty gradient / glass curve) via ffmpeg → WebP.
   Then: **double compression** discovered — ffmpeg lossy + `next/image`
   re-encode at q75. Switched to committing **lossless PNG sources** and letting
   the optimizer do the single lossy pass at `quality` 90–100, AVIF-first
   (better on gradients/dark than WebP). Halftone dither is near-incompressible:
   660KB at q88, 2.4MB lossless.
4. **Human: "abstract has no meaning, thumbnails don't fit the site."**
   The diagnosis that actually mattered: **nothing else on the site is
   pictorial**. Hero, skills, experience are all type. Any imagery in Projects
   will always read as imported from a different website. Shaders, AI abstracts
   and glass icons all failed the same test for the same reason.

**Landed direction:** line-drawn micro components per project, strokes on the
text tokens (so they follow the theme), inside a bento. Solves meaning (a
document tree *is* Jotion), language (strokes on text tokens), assets (none),
and medium (built, not sourced).

Also researched and **rejected**: Apple Icon Composer (macOS only — human is on
Windows), Framer glass plugins (runtime effects inside Framer sites, cannot
export assets; no usable Framer MCP), AI glass-icon generators (the projects
have **no logos**, so the glyph problem sits upstream of the glass problem).

Parallax was built then **removed**: four cards in two rows is not enough scroll
distance to read as depth, and each card wrapped a WebGL canvas so the transform
was real GPU cost for an invisible effect.

**Current state:** shaders, images and `@paper-design/shaders-react` fully
removed. `public/projects/` deleted. Four **empty** bento cells, 2×2 from `md`,
one column below. Text intentionally stripped until the illustrations exist.

## 8. Site-wide borders (today, modelled on pii-ai)

- `components/Section.tsx`: full-bleed `border-t` on the section, inner
  `max-w-5xl` with `md:border-x`. Horizontal rules span the viewport, vertical
  rules mark the content column. **Content width unchanged.**
- **`border-t` only, never `border-b`** — adjacent sections share one line
  instead of stacking a 2px seam. `last` prop for a closing edge.
- `components/SectionHeader.tsx`: label left, optional action right, rule
  beneath. `-mx-4 md:-mx-8` cancels container padding so the rule **meets the
  vertical border-x** rather than floating inside the column. Same trick in the
  hero actions strip and the bento.
- Bento borders live on the **cells**, never the grid: each draws bottom+right,
  last row drops bottom, last column drops right.
- Nav, all five sections, footer and 404 all in the same column, so the vertical
  rules run continuously down the page.
- Vertical rules dropped below `md` (`md:border-x`), matching pii-ai's
  `max-md:border-x-0`.

## 9. Config / build

- `output: "export"` was added then **removed** (server actions needed for the
  contact form). `images.unoptimized` went with it.
- `images: { formats: ["image/avif","image/webp"], qualities: [75,90,100] }` —
  Next 16 **rejects undeclared quality values**.
- `metadataBase` set (OG images were resolving against localhost).
- `robots.ts` + `sitemap.ts` (Velite-driven, published posts only).
- **`history.scrollRestoration = "manual"`** as an inline script in the root
  layout body. Must be a script, not an effect — restoration happens around the
  load event, long before hydration. Without it, refresh renders at top, starts
  the hero reveal, then jumps to the saved position mid-animation. Intermittent
  because it depends which wins the race. Trade-off: back/forward no longer
  restore position natively.
- `/blogs` → `/blog` rename (route, content dir, velite pattern, all links). No
  redirect by choice — old URLs 404.

## 10. Animation lessons (hard-won, cost several rounds each)

These cost real time. Do not relearn them.

- **`filter: blur()` cannot be composited.** It repaints every frame regardless
  of layer promotion. Removed from the hero entrance entirely — opacity +
  transform only. Still present in `AnimatedSection`, `Experience`, `Projects`
  scroll entrances; same fix applies if they ever stall.
- **De-promotion causes a settle jump.** A browser promotes an animating element
  to its own layer then drops it when the animation ends, re-rasterising text at
  a different sub-pixel position. `will-change` must **persist** past the
  animation. Correct here specifically because it is 8 elements animating once.
- **Never round a scroll-linked transform.** `Math.round` replaces smooth
  sub-pixel motion with visible 1px stepping. Use `useSpring` with `restDelta`
  instead — `restDelta` matters as much as stiffness, or the spring emits
  sub-pixel updates long after it looks settled.
- **The hero entrance is CSS, not Framer.** Framer drives from an effect, so the
  server HTML shipped with the name translated 115% down behind its mask and the
  hero was *blank* until hydration. `.hero-line` / `.hero-fade` / `.hero-rule`
  in `globals.css` with `animation-fill-mode: both` and per-element
  `animation-delay`. Framer is now scroll-parallax only.
- `AnimatedSection` still fires on **mount**, not scroll — sections below the
  fold finish animating before you reach them. Only Blogs still uses it; it
  retires when Blogs is rebuilt.
- Turbopack frequently serves **stale `globals.css`**. New `@keyframes` or
  `@layer` rules routinely need a dev-server restart. Two separate "the
  animation is gone" reports were this.
